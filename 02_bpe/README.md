# 02. BPE (Byte Pair Encoding)

## 한 줄 요약
가장 자주 붙어 다니는 두 조각을 하나로 합치는 걸 반복해서 토큰 사전을 만든다.
새 단어는 **합친 순서 그대로** 따라 해서 자른다.

## 왜 필요한가

| 방법 | 장점 | 단점 |
|---|---|---|
| 글자 단위 | 모르는 단어가 없다 | 토큰이 너무 많아 느리다 |
| 단어 단위 | 토큰이 적다 | 처음 보는 단어를 못 읽는다 |
| **BPE** | 자주 나오는 건 크게, 드문 건 잘게 | 둘의 중간 |

## 동작 과정
1. 모든 단어를 한 글자씩 자른다.
2. 나란히 붙은 짝꿍의 개수를 센다. (단어 등장 횟수만큼 가중치)
3. 1등 짝꿍을 합치고, 합친 순서를 기록한다.
4. 정해진 횟수만큼 2~3을 반복한다.

예시 (`hug×3, pug×2, pun×2, bun×1, hugs×1`):
```
u + g  → ug   (6번)
h + ug → hug  (4번)
u + n  → un   (3번)
```
→ 처음 보는 `unhug`도 `['un', 'hug']`로 자를 수 있다.

## 배운 점
- 새 단어를 자를 때는 반드시 **학습 때 합친 순서대로** 적용해야 한다.
  순서가 바뀌면 결과가 달라진다.
- 짝꿍을 셀 때 단어 등장 횟수를 곱해야 한다. 같은 단어를 매번 따로 세는 것보다 빠르다.
- 동점일 때 어떤 짝꿍을 고를지 규칙을 정해 두지 않으면 실행할 때마다 결과가 달라질 수 있다.
- `decode(encode(w)) == w` 왕복 테스트로 정확성을 확인했다.
- 글자 단위로 시작하면 사전에 없는 글자를 처리할 수 없다.
  실제 LLM(GPT 계열 등)은 바이트 단위(256개)에서 시작해 이 문제를 없앤다.

## 시간 복잡도
- 학습: 합치기 1번마다 전체 단어를 훑으므로 O(합치기 횟수 × 전체 글자 수)
- 이 구현은 이해하기 쉽게 매번 처음부터 다시 센다.
  실제 라이브러리는 바뀐 짝꿍만 갱신해서 더 빠르게 만든다.

## LLM과의 연결
`텍스트 → BPE 토큰 → 토큰 ID → 임베딩 → 어텐션 → ...`
LLM이 실제로 입력받는 것은 글자가 아니라 `encode_to_ids`가 만든 **번호**다.
